# Day 9 系统设计：分布式边缘协同 Agent 运行时

> 场景：智能体（Agent）运行在分布于不同物理位置的边缘设备上，面对**弱网、频繁断网、带宽极度受限**的真实环境。
> 传统依赖持续稳定网络（WebSocket / 频繁 HTTP 轮询）的集中式或强耦合架构会直接崩溃。
> 目标：设计具有**高度容错、最终一致性（Eventual Consistency）、状态自愈（Self-Healing）**能力的分布式运行时。

## 1. 约束与物理边界定义 (Requirements & Constraints)

- **网络环境**：RTT 可能从 50ms 骤增至 5000ms+，存在长达数分钟至数小时的**完全断网（Network Partition）**。
- **节点特性**：每个边缘节点有独立本地算力与存储，必须能**完全离线自主决策**。
- **协同目标**：多节点协同完成复杂任务（分布式机器人避障、多设备协同工厂监测、微电网协同电量调度）。

---

## 2. 核心架构设计 (Architecture Blueprint)

采用**解耦的事件驱动 + 基于 CRDT 与 Raft/Quorum 变体的动态混合拓扑架构**。

```
       ┌────────────────────────────────────────────────────────┐
       │           分布式边缘协同 Agent 节点架构 (单个节点)      │
       └────────────────────────────────────────────────────────┘

         [ 物理网络 / P2P 传输 ]
                    │  (弱网 / 间歇性断连 / 自动重连)
                    ▼
         ┌──────────────────────────────────────────────────────┐
         │ 1. 弹性通信层 (Resilient Transport)                  │
         │    - 混合 P2P (QUIC / Thread / Wi-Fi Aware)          │
         │    - 带退避重试 (Exponential Backoff) 的消息队列     │
         └──────────────────┬───────────────────────────────────┘
                            ▼
         ┌──────────────────────────────────────────────────────┐
         │ 2. 状态同步与共识层 (State Sync & Consistency)       │
         │    - CRDT (无冲突复制数据类型) 用于松耦合协同        │
         │    - 动态 Quorum (法定人数) 控制用于强一致性决策     │
         └──────────────────┬───────────────────────────────────┘
                            ▼
         ┌──────────────────────────────────────────────────────┐
         │ 3. 本地持久化与日志层 (Local Durable Ledger)         │
         │    - 顺序追加日志 (Append-Only Write-Ahead Log)      │
         │    - 本地嵌入式 KV 引擎 (RocksDB / SQLite)           │
         └──────────────────┬───────────────────────────────────┘
                            ▼
         ┌──────────────────────────────────────────────────────┐
         │ 4. 本地自主决策 Agent 引擎 (Autonomous Agent Core)   │
         │    - 本地 LLM (INT4) / 确定性状态机                   │
         │    - 降级执行策略 (Graceful Degradation Mode)        │
         └──────────────────────────────────────────────────────┘
```

## 3. 弹性通信层：基于 QUIC 与 P2P 的断线重连

TCP 在弱网、高丢包（>10%）下会因拥塞控制和三次握手导致严重延迟抖动与连接中断。

- **传输协议选型**：基于 UDP 的 **QUIC**（或其上的 HTTP/3）。
  - **连接迁移（Connection Migration）**：设备移动 IP 变化（Wi-Fi ↔ 5G）时，QUIC 无缝保持连接，无需重握手。
  - **多路复用（Multiplexing）**：解决队头阻塞（Head-of-Line Blocking），单流丢包不影响其他数据流。
- **本地消息队列与重试**：
  - 待发消息不直接发，先写本地**持久化未发送队列（Outbox）**。
  - 用**指数退避 + 抖动（Exponential Backoff with Jitter）**，断网期间降低尝试频率省电；网络恢复（Link-state / Ping 探测）后立即批量排空队列。

## 4. 状态同步与共识层：弱网下的“最终一致性”

频繁断网环境下**绝不能**每次决策都用强一致性协议（要求所有节点在线的 Standard Raft），否则任一节点断开整条生产线停摆。采用 **CRDT + 动态 Quorum 混合模型**。

### A. 状态冲突解决：CRDT（Conflict-Free Replicated Data Types）
- 非强一致状态（节点坐标、传感器历史、活跃状态、局部意图）用 **LWW-Element-Set** 或 **PN-Counter**。
- 每个更新附带**逻辑时钟（Lamport Timestamp / Vector Clock）**。
- A、B 断连后各自局部决策，重连时只交换状态增量。CRDT 数学特性（交换律/结合律/幂等）保证**无论到达顺序如何、无需中央服务器，纯本地合并就能最终一致**。

### B. 关键决策共识：动态 Raft（Dynamic Group Membership）
- 关键、不可逆的强一致决策（谁当主控、分配执行器权限）用分区的 **Local Raft Group**。
- **动态法定人数（Dynamic Quorum）**：5 节点中 2 个被隔绝时，这 2 个感知无法满足多数（2 < ⌈5/2⌉ = 3），立即转入**只读/安全模式（Safe Mode）**放弃决策权，避免**脑裂（Split-Brain）**；多数派分区（3 节点）继续提供完整服务。

## 5. 本地持久化与日志：WAL 与状态恢复 (Durable Execution)

防止边缘设备中途断电/崩溃丢失协同状态，Agent 必须**可重放（Replayable）**：

- **WAL（Write-Ahead Logging）**：所有外部输入、协同决策、本地动作在执行完成前，必须先顺序写入本地**追加日志（Append-only Log）**。
- **嵌入式数据库**：用 **RocksDB**（进程内嵌入式 KV，顺序写性能极强，无网络/IPC 开销）。
- **状态重建与重放**：硬件异常重启后重新加载 RocksDB，读取最近 **Snapshot（快照）** + 顺序重放后续 Action 日志，毫秒级恢复到崩溃前精确协同状态。

## 6. 本地自主决策 Agent 引擎：降级执行（Graceful Degradation）

Agent 必须有自我意识，知道自己处于什么网络状态，主动调整“智商”与行为：

```
┌────────────────────────────────────────────────────────────┐
│                   Agent 动态降级决策状态机                   │
└────────────────────────────────────────────────────────────┘

    [ 网络良好 (RTT < 100ms) ] ──────► [ 全功能协同模式 (Collaborative) ]
                                          • 共享全局状态
                                          • 跨节点资源互助
                                          • 调用云端复杂推理模型
                                  │
                                  ▼ (网络恶化 / 丢包 / 间歇断开)
    [ 间歇弱网 (RTT > 2000ms) ] ─────► [ 局部共识模式 (Local Group Only) ]
                                          • 限制与核心邻居的通信频次
                                          • 启动本地 LWW-CRDT 状态合并
                                          • 关键决策走本地多数派 Quorum
                                  │
                                  ▼ (完全断网 / Network Partition)
    [ 完全离线 (Offline) ] ──────────► [ 本地安全自治模式 (Autonomous Safe) ]
                                          • 停止一切跨节点协作请求
                                          • 仅执行本地传感器反馈逻辑
                                          • 切换纯硬编码/轻量本地规则防抱死
```

## 7. 面试官高频追问模拟 (Q&A Strategy)

### 追问 1：离线期间两个节点对同一物理执行器发了冲突指令，重连后 CRDT 判 LWW，但物理动作已错误执行，怎么解决？
**答**：这是“物理冲突与逻辑冲突异步”问题。**物理执行器控制必须用「锁/租约机制（Lease）」，不能用无锁 CRDT**。离线/弱网前，节点须向多数派集群申请该执行器的**独占租约（Lease + TTL）**：网络断开后，持租约节点在到期前拥有唯一控制权；未持租约节点即使离线，本地 Agent 也必须拒绝产生任何物理动作、进入安全等待，从物理根源杜绝冲突。

### 追问 2：网络恢复后大量积压消息瞬间冲垮脆弱边缘带宽（拥塞死锁），如何避免？
**答**：
1. **消息合并与压缩（Delta Compression）**：出队前合并，而非重发几百条。如 IMU 位置积压 50 次，只发最新状态或用卡尔曼滤波压成一条曲线特征。
2. **优先级流量控制（Prioritized QoS）**：分级——Critical Control（高优先，优先排空）、State Sync（中）、Telemetry/Logs（低，仅带宽充裕时发）。用 QUIC 流控限制低优先级流带宽占用。

## 8. 口头表达速记卡（闭眼默背）

- **三边界**：RTT 50ms→5000ms+、可数小时断网、节点须完全离线自治。
- **通信层**：QUIC（连接迁移 + 多路复用抗队头阻塞）+ 持久化 Outbox + 指数退避抖动。
- **一致性**：松耦合状态用 CRDT（LWW/PN-Counter + 逻辑时钟，本地合并最终一致）；强决策用动态 Quorum Raft。
- **脑裂防护**：少数派分区（< ⌈N/2⌉）自动进只读 Safe Mode。
- **持久化**：WAL + RocksDB + Snapshot 重放，毫秒级崩溃恢复。
- **降级三态**：Collaborative（<100ms）→ Local Group（>2000ms）→ Autonomous Safe（断网）。
- **物理冲突**：执行器用 Lease + TTL 独占租约，无租约拒绝动作。
- **重连风暴**：Delta 压缩合并 + Prioritized QoS 分级排空。
